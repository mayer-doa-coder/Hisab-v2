# Field notes

One file per shop visit, named `YYYY-MM-DD-shop-NN.md`. No shop names, no shopkeeper names — use the shop number consistently so visits can be linked across time.

## Template

```markdown
# Shop NN — YYYY-MM-DD

**Type:** (grocery / pharmacy / stationery / tea stall / other)
**Area:** (district / neighbourhood, no street address)
**Observed for:** N minutes

## The notebook
- Page layout:
- Columns:
- What happens on a partial payment:
- What is crossed out, and why:
- Photo: (filename, permission recorded yes/no)

## Numbers
- Credit entries per day (observed or reported):
- Customers with an open balance:
- Median amount:
- Largest outstanding:
- How far back the notebook goes:

## The question that matters
"When did you last lose money because of the notebook?"
> (verbatim answer — concrete past event, not a hypothetical)

"Who owes you money that you've given up on?"
> (verbatim)

## What surprised me

## What this contradicts in our plan
```

**The last two headings are the point of the exercise.** If nothing surprised you, you were not watching carefully enough. Anything that contradicts the plan goes into `docs/DECISIONS.md` — field findings override the plan, not the other way round.
